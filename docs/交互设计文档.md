# 上班族健康助手 — 交互设计文稿（IXD）

> 版本：v0.2（对应 PRD v0.2 / P0 范围）
> 关联文档：《产品需求文档PRD.md》《技术设计文档.md》《设计规范.md》

---

## 1. 设计原则

产品成败取决于"提醒是否被欢迎"，交互设计围绕四条原则：

1. **不打扰是最大的尊重**：一切触达默认克制。宁可少提醒一次，不可多打扰一次。
2. **一触即达，一看即懂**：从通知到"知道该做什么"不超过一次点击、两秒加载。
3. **零决策成本**：用户永远不需要想"做什么"——动作已经选好、时长已经定好，只需照做。
4. **可解释、可控制**：让用户随时知道"它为什么提醒我"和"我怎么让它闭嘴/更勤"。信任感是健康类产品的地基。

## 2. 信息架构与导航

P0 极简两 Tab，避免做成"又一个要逛的 App"——它是后台服务型产品，界面只是提醒的落地页和管理面板。

```
┌ TabBar ──────────────────────────────┐
│  ① 今日          ② 我的              │
└──────────────────────────────────────┘

今日                      我的
├─ 数据源状态卡          ├─ 健康标签档案
├─ 今日概览              ├─ 提醒设置
│   （提醒/完成计数）      │   ├─ 密度三档
├─ 下次预估提醒          │   ├─ 静音时段
└─ （条件）未授权引导      │   └─ 测试提醒
                          ├─ 隐私与数据说明
                          └─ 关于

层级 ≤ 2 级；拉伸页为深链独立页，不挂在 Tab 内。
```

## 3. 核心流程

### 3.1 首启引导（目标 ≤ 90 秒完成）

```
启动
 → [1/3] 价值页："最懂你工作节奏的健康提醒"
          （一句话 + 三点：时机准/懂你/零负担，滑动切换）
 → [2/3] 健康标签（必选，多选卡片）
          「颈椎不适」「肩颈僵硬」「腰部劳损」「眼疲劳」
          「只是久坐，没特殊不适」← 与其他互斥
          选中后下方实时预览一句示例文案（让用户立刻感知个性化）
 → [3/3] 权限引导（逐项，每项一屏：说明用途 → 系统弹窗）
          ① 健康数据（读取活动与久坐记录，仅此而已）
          ② 通知（提醒的唯一通道，可在设置中关闭）
          （Android 无 Health Connect 时先引导安装）
 → 完成页：-first tip「戴上你的手环，接下来的事交给我」
```

规则：任何一步跳过都允许（标签除外），缺失项在首页以引导卡形式延续，不弹窗轰炸。

### 3.2 日常提醒闭环（产品主循环）

```
[后台] 久坐达标 → 通知到达
   ↓ 点击                          ↓ 不点击（15 分钟后自动消失）
拉伸页（深链）                     记一次"未响应"
   ├─ 顶部：AI 建议文案
   ├─ 中部：动作卡片（1~3 个）
   │     点击卡片 → 动作详情（动画+要点+倒计时）
   └─ 底部反馈：✅做完了 ⏰稍后 🌙今天别提醒 🚫别再提醒
   ↓ 反馈
本地频控即时生效 → 上报云端画像 → 影响后续文案与频次
```

### 3.3 反馈的后续行为（用户可预期）

| 反馈 | 系统行为 | 用户感知 |
|---|---|---|
| ✅ 做完了 | 记录完成；当日下次提醒阈值不变 | 首页今日完成 +1，轻量鼓励动效 |
| ⏰ 稍后提醒 | 60 分钟后重提（当日仅 1 次，第二次"稍后"视为"今天别提醒"） | Toast："好的，一小时后再叫你" |
| 🌙 今天别提醒 | 当日静默 | Toast："今天就不打扰了，明天见" |
| 🚫 别再提醒这类 | 该标签类目永久静默，可在设置恢复 | Toast + 设置页出现"已暂停的提醒"入口 |

原则：**每种反馈都有一句拟人回应**，让用户感觉在跟一个懂事的助手打交道，而不是在配置机器。

## 4. 页面详细设计

### 4.1 今日（首页）

```
┌──────────────────────────────┐
│  今日                         │
│                              │
│  ⌚ Apple Watch · 数据更新 5 分钟前 │  ← 数据源状态（>2h 未更新转提示态）
│                              │
│  ┌────────────────────────┐  │
│  │   今天已提醒 3 次        │  │
│  │   和你一起完成了 2 次 🎉  │  │  ← 计数卡（P0 唯一数据展示）
│  └────────────────────────┘  │
│                              │
│  下次提醒预估                 │
│  如果你持续坐着，约 14:30 会提醒你 │  ← 可解释性，建立信任
│                              │
│  [!] 健康数据未授权，提醒未生效  │  ← 条件卡（点击进入授权）
│      去授权 →                 │
└──────────────────────────────┘
```

设计说明：
- 「预估下次提醒」是信任建设的关键——把后台规则透明化，用户理解了机制才不会疑心"它是不是在乱推"；
- 不做周报图表、不做步数排名，P0 克制到极致，与"另一个健康数据 App"划清界限。

### 4.2 拉伸页（核心页面，通知深链落地）

```
┌──────────────────────────────┐
│  ✕                            │
│  💬 坐了一个多小时啦，脖子该抗议了 │  ← AI 文案区（首页屏）
│     ——起来倒杯水，顺便做个颈部拉伸│
│                              │
│  为你准备的 1 分钟             │
│  ┌────────┐ ┌────────┐ ┌─── │
│  │ 颈部侧拉伸 │ │ 收下巴   │ │ …  │  ← 动作卡横滑（按标签匹配）
│  │  40s     │ │ 30s     │ │    │
│  └────────┘ └────────┘ └─── │
│  跳过这个 →                    │
│                              │
│  ────────────────────────    │
│   ✅ 做完了    ⏰ 稍后提醒      │  ← 反馈区常驻底部
│   🌙 今天别提醒  🚫 别再提醒这类 │
└──────────────────────────────┘
```

动作详情（点击卡片进入）：

```
┌──────────────────────────────┐
│  ← 返回      颈部侧拉伸   40 秒 │
│                              │
│   ┌────────────────────┐     │
│   │   [Lottie 示意动画]  │     │
│   └────────────────────┘     │
│   缓慢将头侧向右肩，             │
│   感到左侧颈部轻微拉伸即可，       │
│   不要用力下压。                 │  ← 要点 ≤3 条，口语化
│   × 每侧 2 次                   │
│                              │
│      ┌──────────┐            │
│      │  ▶ 开始   │            │  ← 点击后变倒计时环
│      └──────────┘            │
│      （完成后自动返回列表并标记 ✓）│
└──────────────────────────────┘
```

设计说明：
- 反馈区**常驻页面底部**而非动作完成后才出现——用户不点任何动作也能直接反馈"今天别提醒"；
- 动作时长全部 ≤ 60s，倒计时结束即自动返回，不设连续打卡、不设积分，避免"健身房化"；
- AI 文案区固定尺寸预留（最多两行），避免每次提醒页面结构跳动。

### 4.3 健康标签档案（我的 → 健康标签）

- 卡片多选，同首启 [2/3]；变更后 Toast："已更新，下次提醒会更懂你一点"；
- 每个标签下有「已暂停的提醒」条件入口（对应 🚫 反馈，可恢复）。

### 4.4 提醒设置（我的 → 提醒设置）

| 控件 | 形式 | 默认 |
|---|---|---|
| 提醒密度 | 三档分段选择：更严格(45min) / 标准(55min) / 更宽松(75min)，附一句人话解释 | 标准 |
| 静音时段 | 时间范围选择器 | 22:00–07:00 |
| 午休静音 | 开关 | 开 |
| 自动降频 | 说明项（只读）：负面反馈过多时 App 会自动放宽，并在此显示当前状态 | — |
| 测试提醒 | 按钮："发一条试试 →"（5s 内到达，用真实文案管线） | — |

设计说明：密度用"三档人话"而非分钟数输入框——目标用户不该理解阈值语义；测试提醒让用户在授权后立刻获得一次正反馈，是通知链路的"演示通道"。

### 4.5 通知样式（系统通知栏内的战斗）

```
┌──────────────────────────────┐
│ ⌚ 健康助手 · 现在              │
│ 坐了一个多小时啦，脖子该抗议了——  │
│ 起来倒杯水，顺便做个颈部拉伸？    │
└──────────────────────────────┘
（iOS：即时通知；Android：健康提醒渠道，无声音优先震动，避免会议尴尬）
```

- 文案即产品的脸：≤60 字、口语化、具体动作 + 一句理由，禁止"温馨提示：久坐有害健康"式官腔；
- 同一用户 24h 内文案不重复（缓存指纹去重）；
- 无富媒体、无红点诱导，克制是长期留存的本钱。

## 5. 全局交互状态清单

每个数据页面必须覆盖的状态（AI 生成 UI 时同样按此清单校验）：

| 状态 | 首页 | 拉伸页 | 说明 |
|---|---|---|---|
| 加载 | 骨架屏（计数卡） | 直出静态内容（本地） | 拉伸页不允许 loading |
| 空 | 未有提醒时：友好插画 + "今天还没提醒过你，去忙吧" | 不适用 | 空态也要有人味 |
| 错误 | 数据源断开提示卡（引导重连/授权） | 不适用 | 网络失败不影响提醒闭环 |
| 权限缺失 | 常驻引导卡 | 可浏览不可反馈？否——反馈不需要权限 | 授权路径 ≤ 2 跳 |

## 6. 文案规范（V1）

- **人称**：App 自称"我"，称用户"你"；语气 = 贴心的年轻同事，不是医生、不是客服；
- **句式**：具体动作 + 轻理由 + 短横线，例："坐了一小时啦——起来接杯水，顺便转转肩膀，40 秒就够"；
- **禁止**：感叹号连用、命令式（"必须""请立即"）、恐吓式（"久坐正在摧毁你的脊椎"）、诊断式（"你的颈椎问题加重了"）、用药建议；
- **免责边界**：档案页与关于页固定免责声明："本应用提供的建议不构成医疗诊断，如有持续不适请就医"；提醒文案中不出现；
- **示例库**（静态兜底 + Prompt few-shot 素材，随版本维护）：

| 标签 | 兜底文案示例 |
|---|---|
| 颈椎不适 | "低头一小时了，抬头看看远处吧——顺便做个收下巴，30 秒" |
| 肩颈僵硬 | "肩膀是不是又不知不觉耸起来了？放松，画个圈，一分钟" |
| 腰部劳损 | "坐久了腰会记仇的，站起来轻轻后仰两次就好" |
| 眼疲劳 | "盯屏幕一小时了，看看 6 米外的东西 20 秒，眼睛会说谢谢" |
| 无特殊 | "坐了一个多小时啦，起来走两步，倒杯水也行" |

## 7. 视觉设计规范（v0.2 新增，token 详情见《设计规范.md》）

本产品全套界面采用既有 Pixso 设计稿的设计语言：

### 7.1 色彩语义映射

| Token | 值 | 本产品语义 |
|---|---|---|
| primary | `#27C3B0` | 主操作按钮、选中标签、"去授权"链接、完成态勾选 |
| primary.surface | `#27C3B0` 10% | 选中 chip 底色、AI 建议文案区背景 |
| text.primary | `#28332F` | 标题、正文、AI 建议文案 |
| text.secondary | `#28332F` 50% | 日期、时长、说明文字 |
| text.tertiary | `#28332F` 30% | 占位符、禁用 |
| background / surface | `#FFFFFF` / `#FAFAFA` | 页面底 / 卡片与分区 |
| info（降频提示等） | `#28332F` 50% | 信息类提示，**不用警示红**（避免焦虑感，与"不恐吓"原则一致） |
| danger | `#FF4747` | 仅"清除数据"类破坏性操作 |
| shadow.tint | `#062522` 20% | 卡片阴影（带绿调） |

### 7.2 字体映射

| 交互层级 | 规格（Poppins / 中文 HarmonyOS Sans SC） | 应用 |
|---|---|---|
| display | 24/36 w600 | 首启价值页标题 |
| headline | 18/26 w600 | 计数数字、动作名称 |
| title | 16/24 w600 | 区块标题、反馈回应 Toast 主文案 |
| subtitle | 14/22 w600 | 卡片标题、Tab |
| body | 14/22 w400 | AI 建议文案正文、列表项 |
| caption | 12/16 w400 | 辅助说明 |
| micro | 10/14 w400 | 时长、时间戳、chip 文字 |

### 7.3 形状与组件映射

- 卡片圆角：拉伸动作卡 lg(16)、今日概览卡 xl(24)、小卡 md(8)；**胶囊 chip** 用于健康标签选择（选中态=青绿底白字）与分类；
- 反馈按钮：胶囊形，主反馈"✅ 做完了"用 primary 填充白字，其余用 `primary 10%` 底 + `#27C3B0` 字；
- 图标：Linear 风格线性图标（24×24 视觉 / 44×44 热区）；
- 间距：页面边距 32，卡内 8/16，分区 16。

### 7.4 视觉与交互的联合约束

- 通知文案区（拉伸页顶部）背景 `primary 10%`、圆角 xl、固定两行高度预留——文案变化不引起布局跳动；
- 空态插画占位区域用 `#FAFAFA` 底 + `text.tertiary` 文案；
- 完成动效仅用主色的透明度渐变，不引入新色。

## 8. P1/P2 交互预留

- P1 看板：首页计数卡扩展为可点击进入周视图；通知设置增加"智能时机（AI 频控）"开关；
- P2 对话助手：首页增加对话入口（悬浮或 Tab 扩展，届时重新评估导航结构）；对话中的建议卡片与拉伸页动作卡片复用同一组件。
