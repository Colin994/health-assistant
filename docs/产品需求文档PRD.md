## 1. 产品概述

### 1.1 背景与问题

上班族普遍存在久坐、缺乏活动、颈椎/腰椎劳损等职业健康问题。现有解决方案各有缺陷：

- 手环/手表自带的久坐提醒：固定话术（"该起来活动一下了"），不区分用户身体状况与场景，用户很快疲劳并忽略；
- 健康类 App（Keep 等）：重内容轻触达，需要用户主动打开，对"没时间没动力"的目标人群无效；
- 提醒类工具（喝水 App 等）：无数据支撑、无个性化，本质是闹钟。

核心洞察：**健康行为的改变卡在"触发时机"和"触发方式"上，而不是"不知道该运动"**。一个在你真的久坐一小时、且贴合你身体状态（颈椎不适）、用你听得进去的方式说话的提醒，价值远大于一套健身课程库。

### 1.2 产品定位

面向上班族的 **AI 健康行为提醒助手**：基于手环行为数据识别久坐等工作期不良行为，结合用户健康标签，由 AI 生成个性化提醒与建议，通过轻量动作（拉伸）帮助用户在工作间隙建立健康微习惯。

一句话：**"最懂你工作状态的健康提醒，在你需要的那一刻说一句你能听进去的话。"**

### 1.3 目标用户

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| 颈椎劳损上班族（主） | 25–40 岁，日均久坐 8h+，有颈椎/肩颈不适史，佩戴手环 | 工作期被适时提醒活动，缓解不适 |
| 久坐健康焦虑者 | 意识到久坐危害但缺乏行动 | 不需要思考的低门槛健康干预 |
| 亚健康管理者 | 关注数据与趋势 | （P1）看得见的行为统计 |

前置条件：用户拥有与 HealthKit / Health Connect 同步的手环或手表。

### 1.4 核心价值主张

1. **时机准**：基于真实行为数据（手环活动分段）触发，而非定时闹钟；
2. **懂你**：结合健康标签与反馈历史生成个性化文案，AI 说话像同事不像闹钟；
3. **零负担**：提醒后的行动 1~3 分钟内完成，不需要换衣服、不需要打开课程；
4. **不打扰**：本地频控 + 反馈学习，越用越合拍，而不是越用越烦。

## 2. 产品目标与成功指标

### 2.1 P0 目标

验证核心假设：**基于行为数据 + 个性化文案的提醒，其"完成率"显著优于传统固定提醒**。

### 2.2 指标体系

| 类型 | 指标 | P0 目标（内测参考值） |
|---|---|---|
| 北极星 | 提醒→完成率（点通知且点了"做完了"） | ≥ 25% |
| 核心 | 提醒点击率 | ≥ 40% |
| 健康 | 通知权限保留率（7 日） | ≥ 80% |
| 健康 | 负反馈率（"别提醒"类 / 总提醒） | ≤ 15% |
| 健康 | 周留存（内测） | ≥ 50% |
| 技术 | LLM 文案生成成功率（未降级） | ≥ 95% |

## 3. 用户故事与核心场景

**主场景：颈椎病用户小林的一天**

> 小林，32 岁，程序员，戴 Apple Watch，颈椎不适两年。上午 10 点起进入编码心流，不知不觉坐了 70 分钟。手环判定久坐数据同步至苹果健康，App 规则引擎命中"工作时段 + 连续久坐 55 分钟"。AI 结合他的档案（颈椎不适 + 昨天反馈过肩颈酸）生成提醒："坐了一个多小时啦，脖子该抗议了——起来倒杯水，顺便做个颈部侧拉伸，1 分钟就够。" 小林点击通知进入拉伸页，跟着完成了 1 分钟颈部拉伸，点了"做完了"。下午他开会没空理提醒，点了"稍后"，App 1 小时后再提醒并把这次"忙碌"计入画像。

### P0 用户故事

| 编号 | 故事 | 优先级 |
|---|---|---|
| US-01 | 作为用户，我可以选择我的健康标签（如颈椎不适），让提醒更贴合我 | P0 |
| US-02 | 作为用户，我久坐达标后会收到一条针对我的提醒，而不是千篇一律的话术 | P0 |
| US-03 | 作为用户，点击提醒能立刻看到该做什么动作、怎么做、做多久 | P0 |
| US-04 | 作为用户，我可以用一个动作告诉 App 我的感受（做完了/稍后/别提醒），它会调整后续行为 | P0 |
| US-05 | 作为用户，我可以设置静音时段和提醒密度，App 不会在我睡觉时打扰我 | P0 |
| US-06 | 作为用户，我可以看到今天提醒我了几次、我完成了几次（最小今日概览） | P0 |
| US-07 | 作为用户，我能理解为什么 App 需要健康数据与通知权限，并随时可以撤回 | P0 |

## 4. 功能需求（P0）

### FR-1 首启引导与授权

| 项 | 说明 |
|---|---|
| 目标 | 让用户在 3 步内完成价值传达 + 权限授予 |
| 内容 | ① 价值介绍（1 屏：产品做什么）→ ② 选择健康标签 → ③ 系统权限引导（健康数据 + 通知，逐项说明用途）→ ④ 完成，进入首页 |
| 细节 | 健康标签必选（含"只是久坐，没特殊不适"选项）；权限被拒不阻断进入，首页持续显示"未授权，提醒未生效"的引导卡片；授权流程可随时重进 |
| 验收 | 授权完成率（进入引导→完成三权限）≥ 60%（内测）；每个权限申请前有用途说明页 |

### FR-2 健康标签档案

| 项 | 说明 |
|---|---|
| 内容 | 多选标签：颈椎不适 / 肩颈僵硬 / 腰部劳损 / 眼疲劳 / 无特殊不适；每项可选严重程度（轻微/明显，P0 仅影响文案语气） |
| 约束 | 标签仅存于画像，用于文案生成与动作匹配；修改后下次提醒生效 |
| 验收 | 修改标签后，云端下一条文案的 Prompt 中包含新标签（可通过 advice_log 验证） |

### FR-3 行为数据接入（用户可感知部分）

| 项 | 说明 |
|---|---|
| 内容 | 读 HealthKit / Health Connect 的活动分段与久坐标记；iOS 引导授权苹果健康，Android 引导安装/授权 Health Connect |
| 用户呈现 | 首页显示"数据源：Apple Watch / 已连接的手环"；数据超过 2h 未更新显示温和提示 |
| 验收 | 双端各一台手环佩戴，活动分段可正常读取并驱动规则 |

### FR-4 久坐提醒（核心）

| 项 | 说明 |
|---|---|
| 触发 | 工作日工作时段内，连续久坐达阈值（默认 55 分钟，用户可选 更严格 45 / 标准 55 / 宽松 75） |
| 打断 | 检测到走动/活动即重置累计（用户活动了就不打扰） |
| 频控 | 两次提醒间隔 ≥ 90 分钟（随反馈自适应调整）；静音时段不触发 |
| 文案 | 云端 LLM 生成，≤60 字；失败降级为按标签预置静态文案；同上下文 24h 内命中缓存 |
| 验收 | 真机全天佩戴，工作时段按时触发；静音时段零触发；活动打断后不误报 |

### FR-5 拉伸页（提醒落地页）

| 项 | 说明 |
|---|---|
| 内容 | 按标签匹配动作组合（颈椎→颈部侧拉伸/收下巴等；肩颈/腰背/眼疲劳同理），P0 内置 12~16 个动作，每个含名称、示意动画（Lottie）、时长、要点、次数 |
| 结构 | 顶部：AI 建议文案；中部：今日推荐动作卡（1~3 个，可横滑/跳过）；底部：反馈按钮区 |
| 深链 | 通知点击直达，冷启动 ≤ 2s 展示完整内容 |
| 验收 | 通知→内容完整展示全链路（含冷启动）≤ 2s；动作与标签匹配正确 |

### FR-6 反馈与自适应

| 项 | 说明 |
|---|---|
| 反馈四态 | ✅ 做完了 / ⏰ 稍后提醒（1h 后重提，本日最多稍后 1 次）/ 🌙 今天别提醒 / 🚫 别再提醒这类 |
| 本地即时生效 | 「今天别提醒」「别再提醒」立即写入本地频控，不等云端返回 |
| 降频规则 | 近 7 天负面反馈占比 > 50% → 自动放宽阈值与冷却期，并在 App 内告知 |
| 验收 | 4 种反馈均可在通知内或页面内完成；「别再提醒」后同类提醒次日不再出现 |

### FR-7 今日概览（首页）

| 项 | 说明 |
|---|---|
| 内容 | ① 今日提醒次数与完成次数（轻量，不做完整看板）；② 数据源状态；③ 未授权引导卡（条件显示）；④ 下一次预估提醒时段（基于规则的可解释展示，建立信任） |
| 约束 | P0 不做长周期统计图表（P1），避免做成"另一个数据 App" |
| 验收 | 提醒/完成计数与 advice_log 一致 |

### FR-8 提醒设置

| 项 | 说明 |
|---|---|
| 内容 | 提醒密度三档（严格/标准/宽松）、静音时段（默认 22:00–07:00）、午休静音开关、测试提醒按钮 |
| 验收 | 修改即时生效；测试提醒 5s 内到达 |

## 5. 视觉设计基线（v0.2 新增）

产品采用既有 Pixso 设计稿提取的设计规范（详见《设计规范.md》），与产品定位的适配结论：

- **色彩**：薄荷青绿主色 `#27C3B0`（健康、放松、专业感）+ 墨绿炭文字 `#28332F` + 白底；层级用透明度阶梯（50%/30%/10%）表达，不引入新色相；
- **完成态/成功**沿用主色，不另加绿色；降频提示等信息类状态用 `#28332F` 50%，**不使用警示红**（与"不恐吓"文案原则一致）；`#FF4747` 仅保留给破坏性操作（如"清除所有数据"）；
- **字体**：拉丁/数字 Poppins，中文 HarmonyOS Sans SC；层级靠字重（400/500/600）区分，禁用红色/加粗双重强调叠加；
- **形状与间距**：圆角 4/8/16/24/胶囊，间距 4 的倍数（8 为主节奏），页面边距 32；
- **组件基线**：卡片无描边、胶囊 chip、左图右文低密度列表、Linear 线性图标；
- 全部页面仅浅色模式（P0）。

视觉验收标准：所有页面 UI 实现须通过《设计规范.md》的 token 对照检查，不允许出现规范外色值/圆角/字号。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 最小化采集（仅活动分段/久坐/步数）；不采集心率/睡眠；匿名 UUID，不强制手机号；权限用途全部明示，可撤回 |
| 合规 | 健康标签为敏感信息，单独同意 + 隐私政策专章；LLM 输入脱敏摘要；AI 文案禁诊断/用药表述（详见技术文档 §5.3） |
| 性能 | 冷启动至拉伸页 ≤ 2s；文案接口 3s 超时降级 |
| 可靠性 | 网络不可用时提醒链路可用（静态兜底文案 + 本地频控） |
| 离线 | 拉伸内容全部本地内置 |

## 7. P1 / P2 路线概述

| 阶段 | 内容 | 目的 |
|---|---|---|
| P1 | 数据看板（活动圆环/久坐趋势）、拉伸内容库扩充、AI 频控（个性化时机学习）、地理围栏（到公司才监测）、若定国内补华为 Health Kit | 留存与体验深度 |
| P2 | AI 对话问诊（多轮对话了解状态 → 建议 → 反哺推送策略）、健康知识库 RAG | 差异化护城河 |

## 8. 风险与依赖

| 风险 | 应对 |
|---|---|
| 通知被系统/用户关闭导致产品失效 | 首启讲清价值 + 设置页测试提醒 + 权限状态常驻可查 |
| 手环→手机同步延迟导致提醒滞后 | 文案避免精确时长承诺；引导用户理解"尽量及时" |
| 用户对健康数据授权敏感 | 最小化申请 + 逐项用途说明 + 本地优先架构作为卖点沟通 |
| AI 文案质量不稳定 | 兜底文案体系 + advice_log 人工抽检机制 |
| Health Connect 国内 ROM 覆盖 | P0 明确支持设备范围；国内市场确定后补华为数据源 |
