# UI-002 · 花园与练习场景的平板 / 宽屏适配

**Status:** Candidate（实现与自动化验证完成；待用户确认视觉后晋升至 [design-baseline.md](../design-baseline.md)。Android、iOS 真机与模拟器上的平板走查均未执行。）

- **设计引用：pending。** 现有 Pixso / Figma 画板均为手机竖屏，没有平板画板。本提案的候选修订是 `design/audit_shots/2026-11-24/tablet-layout/` 下的前后对比图：Flutter widget 测试渲染，DengXian 替身字体，0.5 倍缩放，不是真机截图；该目录不入库。
- **既有依据：** [慢植物风格改造实施与验收](../../docs/慢植物风格改造实施与验收-2026-11-16.md) 写明「840dp 起使用 280dp 侧栏」，[走查 M06](../app-walkthrough.md) 写明「宽屏核对侧栏」。木牌方案之后代码里只剩全宽滚动兜底，本提案把这条宽屏行为补齐，并沿用木牌方案的悬浮界面语言。
- **取色脚本输出（边缘色常量的来源）：** 对四时段底图与夜空图的左右外沿 3.5% 宽度按高度九等分求平均，结果写入 [garden_scene.dart](../../feature_game/lib/src/garden_scene.dart) 的 `kGardenEdgeBands` 与 `kStarNightEdgeBands`。

## 改动前的问题

| 场景 | 现象（实测几何） |
| --- | --- |
| 花园 · 横屏平板 | 世界按宽度 cover：1082×810 下底图为 1082×1939，只看到约 42% 的高度，房子与凉亭被裁掉；近排花畦 y=497–701，「押花册 / 商店」在 y≈636–696，操作区压住花畦。 |
| 花园 · 竖屏平板宽 ≥840dp（iPad Pro 12.9"） | 落入为矮窗口和大字号准备的滚动兜底，「押花册」「商店」相距约 930dp。 |
| 接阳光 | 棋盘铺满窗口宽度，托盘固定 112dp；判定窗口是场宽的 7.5%，在 1180dp 宽时比托盘还宽，落点在托盘外也算接住。 |
| 看星星 | 视口框宽度取窗口的 55%，横屏 1366dp 下被拉成约 750dp 的扁框。 |

## 方案

只按可用约束适配，不判断平台或设备。手机竖屏、矮窗口（安全区高度 < 600dp，即手机横屏）与大字号（滚动兜底）的布局不变。

### 花园首页（`GamePhase.idle`，[garden_view.dart](../../feature_game/lib/src/garden/garden_view.dart)）

| 条件 | 世界 | 底部操作 |
| --- | --- | --- |
| 两侧留白 < 24dp（手机、竖屏平板） | 铺满，不变 | 居中，最大 640dp |
| 窗口宽于完整构图，两侧不足 280dp | 收窄到完整构图（约母版 75% 高度）并居中，两侧延展 | 同上 |
| 两侧各 ≥ 280dp（横屏平板、桌面窗口） | 同上 | 移入右下侧栏：押花册 / 商店并排，次数文案，接阳光 / 看星星纵排 |

- 标题、退出按钮、资源牌在三种条件下位置都不变（资源牌仍在退出按钮下方）。
- 侧栏条件下，状态提示改为居中显示在世界顶部，不再横跨整个窗口。
- 取景与侧栏的决策是纯函数 [GardenStage](../../feature_game/lib/src/garden/garden_scene_layout.dart)：世界最窄 440dp，且永远不窄于母版整幅宽度，花畦不会被横向裁切。
- 两侧延展 [GardenFramedScene](../../feature_game/lib/src/garden/garden_scene_layout.dart)：母版左右外沿的分带平均色打底，叠加 8dp 宽缩略图的镜像虚化，再朝窗口边缘压暗 22%；世界左右各 24–48dp 羽化，不超过世界宽度的 7.5%，花畦自 10.5% 起而不受影响。背景、植物、装饰与命中仍在同一源图变换上。
- 缩略图缺图时回退为纯边缘色，并输出 `Garden mirror fallback` 日志。

### 练习区（接阳光 / 看星星，[game_play_area.dart](../../feature_game/lib/src/game_play_area.dart)）

- 安全区高度 ≥ 600dp 且宽于 640dp 时，HUD、进度条、棋盘与底部提示收进居中的 640dp 舞台，背景仍铺满窗口。
- 接阳光：棋盘先按 480dp 排布，再整体等比放大（上限 4/3），托盘、光滴与判定窗口保持手机上的比例。玩法坐标本来就是归一化的，时长、阈值与计分没有改动。
- 看星星：舞台比窗口窄时，夜空铺满窗口（完整构图居中，两侧用夜空边缘色延展），棋盘不再自绘夜空；舞台宽度不超过夜空图，HUD 与棋盘不越过画面边缘。手机上仍是棋盘内自绘夜空。

## 受影响的界面与状态

| 路由或组件 | 状态 | 变化的动作与去向 |
| --- | --- | --- |
| `GardenView` | 花园首页，默认态 | 点花畦 → 选种 / 植物详情面板；押花册、商店、接阳光、看星星去向不变，只在宽窗上换了位置 |
| `GardenView` | 次数用尽、状态提示 | 文案与去向不变；侧栏下次数文案保持单行 |
| `GamePlayArea` | 接阳光练习、暂停、提前完成 | 去向不变 |
| `GamePlayArea` | 看星星练习、暂停、提前完成 | 去向不变 |
| 不变 | 准备 / 校准 / 错误、结算遮罩、底部面板、弹窗 | 已有限宽，未改动 |

## 检查

- 共用走查用例：W04–W08（花园资源牌、投入、商店、押花册、练习说明、退出），M02（两种练习的相机流程），M06（方向与可读性），M10（逐个花畦可点击）。建议在平板横屏、竖屏各走一遍。
- 自动化：feature_game 新增 [wide_window_test.dart](../../feature_game/test/wide_window_test.dart) 12 项（取景决策、延展组件、舞台宽度与缩放）；[garden_ui_test.dart](../../app/test/garden_ui_test.dart) 新增 40 项（7 种平板 / 窗口尺寸 × 1.0 与 1.3 字号 × 浅暗主题的花园几何，6 种尺寸 × 浅暗主题的练习舞台）。
- 回归：全工作区 `dart run melos run analyze` 无问题；`dart run melos exec --dir-exists=test -- "flutter test"` 196 项通过（另有 4 项 macOS 专属 golden 在本机跳过）。
- 手机不变：390×844 下花园、夜景花园、接阳光、看星星、结算五个场景的渲染，改动前后逐字节一致。
- 契约脚本：`check_project_skills.py`、`garden_asset_inventory.py`、`device_walkthrough.py --check-contract` 通过。`check_design.py` 在 Windows 上会报 40 处命中，全部来自样式定义文件 `garden_ui_theme.dart`：脚本的豁免名单用正斜杠路径，Windows 下比较不上。按 CI 的路径口径复算为 0 命中，本次没有改这个脚本。
