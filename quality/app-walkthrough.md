# Health Assistant 全应用测试与走查

适用范围为当前可从 Android 和 iOS 正常入口使用的功能，以及 dev 渠道专属入口。以[移动端契约](mobile-design-and-walkthrough.md)、[用例编号](mobile-walkthrough.json)及[批准设计基线](design-baseline.md)为准。设计引用缺失时记 pending。测试使用专用安装和固定数据，人工走查记录实际结果。

## 执行顺序

1. 在根目录按 [CI](../.github/workflows/ci.yml) 准备依赖与生成代码，执行 `melos run analyze`、`melos run test`、`python3 tools/device_walkthrough.py --check-contract`。保留源码快照、SDK、日志和退出码。
2. 在 `app/` 分别执行 `flutter build apk --debug --flavor master` 和 `flutter build ios --debug --no-codesign`。模拟器可运行 [计步通道测试](../app/integration_test/steps_channel_test.dart) 和 [花园面板测试](../app/integration_test/garden_panel_simulator_test.dart)，命令为 `flutter test integration_test/<测试文件> -d <模拟器 ID>`，Android 追加 `--flavor master`。记录系统版本、命令、日志。感应器、权限及通知的验收安排在真机。
3. 两端真机用同一源码、设计引用和 fixture 运行共用自动套件 W01–W10。用 `flutter devices` 获取 ID，逐台执行 `python3 tools/device_walkthrough.py --device <id> --design-ref '<revision>'`。dev 渠道加 `--flavor dev`。保留每次独立生成的 `report.json`、`flutter.log`。
4. 恢复正常入口后逐项走人工用例。走查脚本传入 `--no-uninstall`，测试仍会覆盖安装同一应用标识的构建。iOS 的 dev 和 master 共用 Bundle ID。默认与 dev 渠道分开记构建标识。升级时在专用旧安装上连续取证，保留应用数据。每个用例记录实际值与截图、录屏或日志引用；机器报告初始人工状态为 pending。

## 两端人工走查

| 用例 | 步骤和通过条件 | 留证 |
| --- | --- | --- |

| M02-camera-pose | 初始锁定时点看星星，查看解锁条件且不触发相机权限。用已解锁存档对两种练习分别验证允许、拒绝、设置撤权及恢复。允许后完成校准、真实动作和结算，核对实际分数、资源入账和返回花园。 | 授权分支录屏、校准及前后余额、结算记录。 |
| M03-step-count | 初始允许后记录数值，手持设备走 20 步，等回调并记差值。验证拒绝、撤权、「去设置」、未修改返回和重新授权恢复。Android 核对身体活动；iOS 核对运动与健身并记录批量回调时间。 | 权限前后、系统设置落点、起止步数和时间。 |
| M04-notification | dev 渠道从测试提醒或演示节奏验证前台、后台和结束进程后的实际送达；检查默认点击到拉伸，若展示花园通知操作则核对对应落点。拒绝通知后应用仍可用。Android 核对非精确调度的实际送达。测试静音时关闭会忽略静音的演示节奏。 | 各状态的计划／实际时间、标题、正文、动作及落点。按下方「M04 通知内容核对」逐项记录。 |
| M05-background | 在两种相机练习中分别切后台、锁屏后恢复；核对退出时无相机占用、重入可校准且不重复结算。应用内返回及 Android 系统返回、iOS 返回手势按可用方式各走一遍。 | 生命周期录屏、相机占用、余额和结算次数。 |
| M06-accessibility | 首启、主导航、提醒表单、详情计时、花园面板和练习结算在浅暗、最大字号、横竖屏、减少动态效果下可读可操作。窄屏能滚到底，宽屏核对侧栏。用 TalkBack／VoiceOver 确认焦点顺序、按钮标签和开关状态。 | 记录显示条件，留关键区域截图及读屏录屏。 |
| M07-disk-persistence | 设置与标签保存、种植、投入、购买后结束进程重进，核对配置、地块、余额和已拥有状态不重复扣费。存储变更另执行[覆盖升级步骤](mobile-design-and-walkthrough.md#提醒配置存储变更)。 | 冷启动前后值、测试构建标识、截图。 |
| M08-reminder-settings | 逐个选择 45／55／75 分钟档位，分别切换喝水、护眼、午休。静音选择器分别在开始、结束处取消，结果保持；相同起止提示后保持；保存跨午夜范围。退出重进核对值，正常节奏下验证当前轮继续，次轮按新配置运行，静音区间暂停。关闭过久坐后重选档位可恢复。 | 设置前后值、取消及相同时间录屏、轮次与时段日志。 |
| M09-stretch-feedback | 用 dev 拉伸入口或真实通知打开拉伸。逐项打开动作详情验证初值和返回，标注 40、30、60 秒的动作倒计时分别为 0:40、0:30、1:00；至少一次走完开始、暂停、继续和完成。单独核对关闭、「本次不做」、花园入口及返回。分别用可复位状态走做完了、稍后提醒、今天别提醒、关闭此类提醒，记录完成数和后续提醒；引擎预期按现有单元用例核对。 | 每种反馈前后状态及下一次提醒时间、详情计时录屏。 |
| M10-garden-economy | 逐个地块验证可点击；空地选种，已种地块投入，按已有阶段触发收获或清理，分别检查确认与取消。验证连续点击、资源不足、已拥有商品、锁定种子和可兑换种子，核对余额、地块和押花册数量。耗尽每日练习次数后再点练习，显示休息提示，核对次日恢复。 | 每项操作的前后资源值、阶段、收藏与配额。 |
| M11-app-navigation | 切换「今日」「我的」「设置」，点今日倒计时入口进入提醒设置并返回。查看下次提醒和可出现的降频提示；验证刷新、已读及返回状态。「我的」验证标签添加和编辑、选「只是久坐」与身体状况互斥、保存后关联提醒开启。「设置」验证隐私返回、手表提示及关于版本展示。dev 核对引导、拉伸、花园风格 Demo、锚点校准、两种练习预览与结算预览能打开和返回，并在 M04 验证测试提醒及演示节奏；master 核对相应入口隐藏。 | 按入口记录目标页面、返回位置、实际状态及渠道。 |

## 待处理的验收差异

| 用例 | 已观察结果与验收预期 |
| --- | --- |
| M11 · 标签放弃 | 宿主走查确认返回时仓库未写入，重新打开时仍残留未保存勾选。已确认的预期是返回即丢弃，重开只回显已保存标签。W09 覆盖写入与保存返回，重开草稿按 M11 单独判定。 |
| M09 · 带次数的动作时长 | 代码将时长和次数的数字拼在一起，「40 秒 · 每侧 2 次」得到 402 秒，「30 秒 · 2 次」得到 302 秒。已确认的预期分别是 40 秒、30 秒；现有实现待修复，60 秒动作已有计时回归。 |

设备报告按 [验收契约](mobile-design-and-walkthrough.md#acceptance) 分开记录。未执行写 pending，受设备、环境或前置状态阻塞写 blocked 并附原因。人工证据和自动报告齐全后，分别判定两端结果。

| 护眼提醒 | 近视（当前引导和标签编辑无此选项） | 把视线从屏幕移开，看看远处，持续 20 秒。 |
| 测试提醒 | dev 渠道手动发送 | 如果你看到了这条通知，说明即时通知可以显示。 |

1. 单独发送测试提醒，核对实际标题和正文。再逐类启用久坐、喝水、护眼，用演示节奏核对真实类别。分别记录引擎即时发送和系统预排的内容。手动测试通知只覆盖即时发送。
2. 核对无匹配标签、单个匹配标签和多个匹配标签。引擎即时发送按标签集合中第一个可匹配项取文案，系统预排使用默认文案。记录标签、触发路径、计划时间、实际时间、标题、正文和截图或录屏；同时观察近同时触发时哪一条内容最终可见。
3. 展开通知查看完整文字及动作。当前所有类别和测试通知共用「拉伸 1 分钟」「去花园接阳光」。分别核对点击正文和拉伸按钮进入拉伸页、花园按钮进入花园，并记录动作是否显示、实际落点及其是否符合正文引导。Android 展开通知，iOS 长按展开；冷启动场景在完成引导后检查。
4. 分别核对常规节奏和演示节奏。检查正文声称的时长或行为是否有实际依据，确认关闭类别及静音期间的表现时使用常规节奏。没有送达的用例记录送达状态，内容标为未验证。

当前类别与落点待确认：

- 久坐文案仍可匹配眼疲劳和咽干易上火。两条正文均以起身活动为主，分别带出看远处和接水。多标签时首个命中会影响最终正文。
- 喝水和护眼正文的动作清楚，但通知按钮和默认落点仍沿用拉伸／花园，正文与点击后体验不一致。系统预排正文未使用标签，需要对照 PRD 的个性化目标确认是否接受该差异。
